## 0. 一句话定位

本地运行的求职自动化系统：零 LLM 的确定性规则引擎给每个 JD 打分（技术 30% / 方向 30% / 经验 15% / 文化 15% / 地点 10%）→ 在 Boss 直聘 / 51job / 猎聘 上按防风控节奏拟真投递 → 全流程落本地 SQLite → 回复扫描、邮件分流、数据复盘。
**目标不是"投得多"，是"真人接触数"（回复 / 约面 / 要简历）最大化。**

## 1. 现状基线（已具备，避免重复建议）

- **架构**：单一事实源 SQLite（`store.py`）；投递状态机 `APPLIED / UNCERTAIN / FAILED`；失败归因 9 阶段 × 23 枚举；五维评分引擎可解释、可回归。
- **风控**：Kill Switch、跨进程日/小时双熔断、夜间禁投、公司去重、平台分池限额（Boss 150 / 51job 100 / 猎聘 20 条/日）、登录态核验、站外卡片拦截、全局 Chrome 互斥锁。
- **质量**：PII 门禁（fail-closed）+ CI + 分支保护 + 发布七步检查；单元 + 回归测试数百项；公开仓库零个人数据。
- **新近加固**：多平台隔离、届别/方向/制度三类硬闸收敛、邮件分流（放行表优先于黑名单）、HR 自动直回（已授权开启；护栏 = 事实核查 + 发送前双闸 + 每批 ≤5 条 + 间隔 75-105s）。
- **配套**：浏览器扩展（JD 提炼 / 回复辅助）、只读决策看板、Web 演示站（多人画像版）、客户端试运行包（Client Trial）。

## 2. 已知缺口（本路线图针对的 7 件事）

1. **送达验证残角**：点击成功 → "消息真发出"的证据链仍有盲点。Boss 上一批投递全落 UNCERTAIN、"聊天页未找到会话"、发送留痕未落账；51job 只认按钮文案变化（平台静默失败不处理）；猎聘会下发风控页假死。
2. **回复观测不全**：已读/回复自动回填目前只覆盖 Boss；51job 的回复字段从未被写过（"0 回复"可能是观测盲区而非事实）；猎聘未接。
3. **作息闸空转**：51job 列表卡片没有 JD 正文 → "至少双休"这类硬规则在该平台无从判断，只能等 HR 互动后按状态机问询。
4. **薪资上限误杀**：上限红线的判定方式对 AI 主线整批误杀最对口的岗位（例如深圳正常行情的 20-36K 岗被拦）。
5. **直投通道未工程化**：漏斗显示"海投 → 回复≈0"主要是**通道问题**（人没看到你），官网/邮箱直投 + 内推（30 家样本门槛）没有系统化承载。
6. **渠道扩容**：鱼泡直聘适配器停在侦察阶段（登录墙 + 类名随机化；文本定位方案已定，未写适配器）。
7. **产品化线脱节**：Web 演示站 / 客户端试运行包与主线代码没有建立发布节奏。

## 3. 迭代升级点（建议 4 个版本；版本名可改）

### V5.6 「送达可信」——把"已投递"变成可证明的事实

1. **复核并修复 Boss 送达疑案**：逐条核查真实落点（是否走了默认招呼语路径 / "已读"回执的时间语义 / 发送留痕为何未落账），修复后把事故原文固化成回归用例。
2. **三平台统一"终态证据链"**：每次发送以 DOM 证据收尾（会话已打开 + 消息在会话内可见 + 留痕文件一致），三者不一致一律落 `UNCERTAIN` / `send_failed`，绝不进"已投"。
3. **UNCERTAIN 归零运动**：把 UNCERTAIN 当最高优先级故障处理（同一平台连续整批 UNCERTAIN = 发送链路坏了，先修再投，禁止拿它当"投出去了"报数）；战报固定三态分列（验证送达 / 未确认 / 失败）。
4. **留痕一致性**：`self_sent` 留痕完整率 100%（含默认招呼语路径）；去重语义写进文档，避免"留痕条数 ≠ 发送条数"被误读。
5. **仓库收口**：待发布的加固批次走 PR 流程合并；建立按版本记事的 CHANGELOG。

**验收**：新事故样本全部可复核可复现；三平台各保留 1 条"按钮 → 会话 → 留痕"完整证据链样例；UNCERTAIN 率先测基线、再定下降目标。

### V5.7 「接触优先」——漏斗口径从"投递数"扭到"真人接触数"

1. **回复观测全平台**：Boss（已有）+ 51job（镜像 / 半自动读取）+ 猎聘（消息中心，若可达）；`read/replied/interview` 全量回填进库。
2. **51job 回复渠道工程化**：iPhone 屏幕镜像 + Mac 剪贴板的半自动流水线（批量生成草稿 → 一句话批准 → 逐条粘贴发送，含节奏护栏）。**不做**平台自带的 AI 批量回复（绕开审核与口径）。
3. **自动直回质量闭环**：每批抽样人工抽检 + 月度误发/口径审计；拒绝类 8-15 字风格守住；事实护栏双闸守住。
4. **接触漏斗看板**：按 平台 × 线（AI 主线 / A 池 / B 池）× 周，统计 接触数 / 回复率 / 约面数，替代"投递量"当头条指标。
5. **约面接管**：一旦出现约面 / 要简历，自动生成"公司核查 + 面试准备包"（面试准备模块已有，接进流程）。

**验收**：任何平台的"0 回复"都必须给出观测结论而非盲区；接触漏斗周报稳定输出。

### V5.8 「渠道扩容与精准化」

1. **鱼泡适配器落地**：`platform_yupao.py`（文本定位、跳过校招站、接过渡线规则），登录后真机 smoke 投 1 条才算验收。
2. **薪资红线分线**：主线上限放宽或分线（例如 AI 主线按新行情设上限、其余线维持严格），回归样本钉死：21-31K / 20-36K 放行，66K+ 仍拦。
3. **制度判断补强**：对高潜岗位拉详情正文（凡低成本的平台），让"双休闸"真正跑起来；拿不到正文的维持"HR 互动后问询"状态机。
4. **去重与防重发**：公司名归一化去重、改标题重发检测定期跑（模块已有）。
5. **"候选清单制"半自动模式（可选开关）**：生成"今日候选 + 招呼语草稿"，人工点投；与全自动并行做 A/B，比接触率。

**验收**：新平台有真机投递证据；分线红线误杀率 0（回归覆盖）；制度闸覆盖比例可量化。

### V6.0 「直投工程 + 产品化分支」（方向性版本）

1. **直投/内推线工程化**：官网/邮箱直投的跟踪表 + 跟进节奏（follow-up）+ 30 家样本目标；外企渠道（含职业社交档案）纳入同一漏斗。
2. **多简历线实验重启**（词表已统一，具备统计前提）。
3. **产品化分支（与求职主线解耦）**：Web 演示站 / 客户端试运行建立"反馈 → 修复 → 发布"节奏，或明确冻结。
4. **套件一体化**：扩展 + 引擎 + 看板统一叙事与指标口径（口径单点在 `jobintel/src/scope.py`）。

**验收**：直投样本 ≥30 家且接触率可对比；产品化分支"要么有节奏、要么正式冻结"。

## 4. 统一验收口径（所有版本共用）

- 第一指标：**真人接触数**（回复 + 约面 + 要简历），按周。
- 第二指标：验证送达率 / UNCERTAIN 率 / 分平台回复率。
- 安全指标：风控事件 0；PII 0 泄漏；夜禁与限额 0 违反。
- 纪律：任何新规则必须由**真实误判案例或回归测试**驱动，不允许"为了更完善"而新增。

## 5. 给外部模型的讨论议题（重点）

1. 在反检测约束下，"送达验证"还有哪些可靠证据面（DOM / 网络 / 时间线）可以补？如何把 UNCERTAIN 压到接近 0 而又不虚报？
2. 没有网页聊天端口的平台（51job），回复自动化的最优形态是什么？（镜像自动化 / 半自动流水线 / 完全人工，各自的成本-风险对比）
3. 从"海投"迁移到"直投 / 内推"，系统该怎么改（数据模型、跟踪、跟进节奏）？哪些能自动化，哪些必须人工？
4. 规则引擎与 LLM 的边界是否需要再平衡：哪些判断值得引入模型，哪些必须保持确定性、可回归？
5. 公开仓库 + 数据本地化的安全模型还有什么提升点（可公开 / 不可公开的切分与门禁）？
6. 转化率最大化的实验设计：小样本 + 右删失（还没等到回复）场景下，A/B 怎么做才有统计意义？
7. 若做产品化（给第三方用），最应该先砍 / 先保的功能是什么？
8. 有没有被忽视的渠道（新平台 / 新形态）值得接入？
